# Grove v0.2.0-beta1

v0.2.0-beta1 promotes the Grove APIs to beta. It adds `grove.io/v1beta1` and `operator.config.grove.io/v1beta1`
and makes `grove.io/v1beta1` the version that Grove stores. The new versions behave the same as `v1alpha1`; they
only drop fields that Grove no longer uses. Read [Upgrading to v0.2.0-beta1](../user-guide/upgrading-to-v1beta1-v0.2.0-beta1.md)
before upgrading.

## API changes

- **`grove.io/v1beta1`** is served and stored for PodCliqueSet, PodClique, PodCliqueScalingGroup,
  ClusterTopologyBinding and PodGangMap. The operator reads and writes only `grove.io/v1beta1`.
- **`grove.io/v1alpha1`** is still served and deprecated, and is unchanged. The API server returns a deprecation
  warning for every `v1alpha1` request, and converts PodCliqueSets between the versions through the operator's
  conversion webhook.
- **`topologyConstraint.packDomain`** is removed from `grove.io/v1beta1`. Use `topologyConstraint.pack.required`.
  A `packDomain` stored by an earlier release, or set through `grove.io/v1alpha1`, is converted to `pack.required`.
- **`PodCliqueSetStatus.podGangStatuses`** is removed from `grove.io/v1beta1`. Grove never set it.
- **`operator.config.grove.io/v1beta1`** is the operator configuration version that the Helm chart renders. It
  drops `KaiSchedulerConfiguration`. The operator still accepts `operator.config.grove.io/v1alpha1` and logs a
  deprecation warning.
- **`scaleConfig.minReplicas`** of a PodClique or PodCliqueScalingGroup now defaults to its `minAvailable` instead
  of its `replicas`, in both versions, so the autoscaler can scale in down to `minAvailable`. The default is
  applied when a PodCliqueSet is created or updated; PodCliqueSets that already have `minReplicas` keep it.
- **PodGang** stays at `scheduler.grove.io/v1alpha1`.
- The `grove.io/v1alpha1` and `operator.config.grove.io/v1alpha1` Go packages remain, and are deprecated.

## Upgrade and downgrade

- The upgrade does not rewrite existing objects. They stay stored as `grove.io/v1alpha1` until they are next
  written, and `status.storedVersions` of each CRD becomes `["v1alpha1","v1beta1"]`. A later release migrates the
  remaining objects before it stops serving `grove.io/v1alpha1`.
- `grove-install-crds prepare-downgrade` moves the objects back to `grove.io/v1alpha1` and removes
  `grove.io/v1beta1` from the CRDs, so that a Helm rollback to v0.1.0-alpha.16 succeeds.
- The chart's `service.name` is now honored by the webhook certificates and by the conversion webhook of the CRDs.
- CI runs an upgrade from the latest v0.1.x release and a downgrade back to it.

## Action required

- Upgrade from a v0.1.x release, and apply the v0.2.0-beta1 CRDs as part of the upgrade, for example with
  `crdInstaller.enabled=true`.
- Move your manifests API version to `grove.io/v1beta1`, and replace `packDomain` with `pack.required`.
- If you provide your own operator configuration file, you can keep `operator.config.grove.io/v1alpha1` for now.
  Move it to `operator.config.grove.io/v1beta1` before a release drops `operator.config.grove.io/v1alpha1`.
- If you use the Go API packages, move from `github.com/ai-dynamo/grove/operator/api/core/v1alpha1` to
  `github.com/ai-dynamo/grove/operator/api/core/v1beta1`, and from `config/v1alpha1.DecodeOperatorConfig` to
  `config.DecodeOperatorConfig`.
